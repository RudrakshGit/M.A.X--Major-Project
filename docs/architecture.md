# Architecture

## Stack

| Layer | Choice | Why this one |
| --- | --- | --- |
| Framework | Next.js App Router, TypeScript | Server Components keep the client bundle small |
| Styling | Tailwind + shadcn/ui | We own the component source; no library lock-in |
| Database | Neon Postgres, free tier | Auto-resumes after idle; Supabase free pauses after 7 days and needs a manual resume — a demo-day failure mode |
| ORM | Drizzle | Typed schema, small, edge-friendly |
| Auth | Better Auth | Free, self-hosted, Drizzle adapter, no vendor account |
| AI | Vercel AI SDK | One interface; swapping provider is one line |
| LLM primary | Groq | Does not train on prompts on any tier; fastest time-to-first-token, which matters most on a weak network |
| LLM fallback | Gemini free tier | Free tier trains on submitted data — disclosed in consent, and no PII is ever sent |
| Hosting | Vercel Hobby, region `bom1` | Free, non-commercial, Mumbai region |
| UI proof | Playwright headless | The in-app browser pane runs hidden; computed styles are unreliable there |

Everything is free and needs no credit card.

## The one pattern to follow

```
Zod schema  ->  Server Action  ->  UI
```

The schema is the contract. It validates at the boundary and types both sides.
Write it first, always. There is no separate REST API to keep in sync, and no
MCP layer — those belong to a production platform, not to this project.

The single exception is `src/app/api/chat/route.ts`, which streams. It still
calls the same action layer underneath.

## Folders

```
src/
  app/                 routes, layouts, route handlers
  features/<domain>/   a domain owns its UI, actions and schemas together
    chat/ mood/ screeners/ journal/ journeys/ resources/ campus/
  safety/              classification, output guard, escalation, golden tests
  ai/                  provider abstraction, prompt assembly, memory, PII strip
  db/                  Drizzle schema, migrations, queries
  content/             journeys and resource content as typed data
  ui/                  shared primitives generated by shadcn
```

A feature folder owns its own Server Actions and Zod schemas. Cross-feature
imports go through the feature's `index.ts`, never into its internals.

Organise by ownership and change reason. Do not split a file to hit a line
count, and never split cohesive content data or generated files.

## Rules that CI enforces, so prose does not have to

- Server Components by default; a `"use client"` island needs a PR reason
- No LLM call outside `src/ai/`, no model call that skips `src/safety/`
- No hex colours or arbitrary radii outside the token file
- First-load JS stays within [`performance.md`](performance.md)

## Deployment

Live at **https://max-rudrakshm099-7145s-projects.vercel.app**, public. The
build runs `next build` only — schema changes go through `npm run db:migrate`
as a deliberate step, never automatically at deploy time. Neon's free tier has
no automatic backups, so take a manual dump before a destructive migration.

## Environments

One environment. `main` deploys to production on Vercel; preview deployments
come from pull requests. Trunk-based: short-lived branch, PR, squash merge into
a protected `main`. No staging branch — a four-person team does not need three
permanent branches, and a preview URL is a better staging than a stale branch.
